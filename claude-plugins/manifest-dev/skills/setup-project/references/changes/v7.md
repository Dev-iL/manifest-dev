# Surfaces v7

- Where a project keeps the harness, it commits no evidence: a run still writes its summary, and a
  failed run its logs, to the evidence directory, which the tool has git ignore, so a failure
  explains itself in the run that met it and nothing a run writes lands in a pull request.
  Evidence the project committed under an earlier version is removed from the repository.
- A recipe has no status: `list` shows each recipe's kind and ask-first mark, `verify affected`
  picks what a change runs from its diff, and each run says what it found. `judge` goes, and what
  every harness owes no longer includes statuses from evidence.
- A fixed-workload scenario's time line is a `Line: <seconds> s on <kind of machine>` field in its
  recipe, one per kind of machine. A run on another kind reports its time and compares nothing. A
  crossing counts only when the confirming run `drive` starts at once crosses too. No run moves a
  line on its own: `verify line` writes a first or lower line, `verify raise` writes the new line
  with its reason, and `verify freeze` writes a level naming the debt Ticket, each into the recipe
  in the change that changes the check. The upgrade first moves each timed scenario's current line
  from its latest evidence into its recipe.
- `verify affected` lists a recipe covering the whole tree among those a change touches, and
  still lists as uncovered a changed path only that recipe covers.
- Lines that tell runs or contributors to commit evidence are rewritten, in the project context
  file, the harness's settings and recipes, and the contributor docs they point to; the
  verification bullet's own wording is unchanged.
- A project that verifies its own way gains nothing here.
